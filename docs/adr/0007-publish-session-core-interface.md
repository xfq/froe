# Publish one session interface for terminal and graphical adapters

Froe will publish `@xfq/froe/core` around one deep `FroeSession` module. `openFroeSession` owns configuration, credential, provider, recorder, approval, sandbox, action runtime, project-instruction, Tavily, and MCP composition. The returned interface exposes only serializable status, one bounded run at a time, and idempotent close. The existing CLI becomes a terminal adapter over this interface; a graphical application can provide another adapter without importing internal `dist` files or parsing terminal output.

Session events carry an interface version, session ID, run ID, and monotonic sequence. Approval requests carry a unique ID, their safety scope, destructive classification, and only the decisions the core permits. Presentation adapters may display events and collect a decision, but approval policy, action execution, cancellation, and resource cleanup remain in the core. Workspace and additional-directory authority stay fixed for a session, concurrent runs fail rather than queue, and records remain audit evidence rather than a resume protocol.

This rejects exposing `runTask`, `ActionRuntime`, `McpManager`, provider construction, or credential storage as the application interface. Those modules retain useful internal seams and tests, but requiring each frontend to compose them would duplicate lifecycle and safety behavior. It also rejects using the CLI text stream as the graphical integration interface because terminal rendering is not a versioned protocol and cannot express structured approvals reliably.
