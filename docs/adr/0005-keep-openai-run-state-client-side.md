# Keep OpenAI run state client-side by default

Froe will send Responses API requests with `store: false` and keep the current run's continuation items in adapter memory instead of depending on remotely stored response IDs. The adapter also requests server-side context compaction at a user-configurable token threshold. When a response contains a compaction checkpoint, that checkpoint and the following output replace all earlier continuation items; setting the threshold to `null` omits the request parameter for compatible endpoints that do not support it. A compaction event records only previous and retained item counts plus the configured threshold, so the operation is auditable without persisting the opaque checkpoint. This increases adapter complexity and prevents first-release resume support, but avoids opting source-bearing response state into the API's default application-state retention; it does not claim to disable separate provider abuse-monitoring retention.
